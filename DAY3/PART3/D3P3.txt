#GET VS POST:
GET:Used to fetch/read data
>EXAMPLE:
    app.get("/profile", (req, res) => {
    res.json({ name: "admin" });
     });

POST:POST:Used when client sends data to backend for processing / creating / saving / checking.
>EXAMPLE:
    app.post("/login", (req, res) => {
    res.json({ message: "Login route hit" });
    });

SOME CONFUSIONS:
How POST Works:
Suppose Thunder Client sends:{
    "username": "RIDDHI",
    "password": "1234"
}
to:POST http://localhost:3005/login
Then Express receives it here:
app.post("/login", (req, res) => {
The sent data becomes:req.body
So:
req.body.username is:RIDDHI
and:req.body.password is:1234
Then your backend checks:
if (username === "RIDDHI" && password === "1234")
If true, server sends:
{
    "success": true,
    "message": "Login successful"
}
If false, server sends:
{
    "success": false,
    "message": "Invalid credentials"
}
-----------------------------------------------------------
What is req.body?body means:
the data sent inside the request
For POST requests, client usually sends data in the body.
Example request body:
{
    "username": "RIDDHI",
    "password": "1234"
}
Then in Express:req.body becomes:
{
    username: "RIDDHI",
    password: "1234"
}
So:
req.body.username
gets username.
req.body.password
gets password.
Why app.use(express.json())?
This does not post info.
It means:
Express, if JSON data comes in request body,please read it and convert it into a JS object.
Without:app.use(express.json());
this:req.bodywill be:
undefined
because Express won’t understand the JSON data.
Why not use GET for login?
Because GET is for reading/fetching data.
Login sends sensitive data:
{
    "username": "RIDDHI",
    "password": "1234"
}
So we use POST.
Simple rule:
GET  = give me data
POST = here is my data, process it
Login is:
here is username/password, check it
So login uses POST.
